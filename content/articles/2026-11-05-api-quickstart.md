## 一、先确定这次调用属于哪一类

数眼智能的[聊天文档](https://doc.shuyanai.com/doc-8784048)列出对话端点 `POST https://platform.shuyanai.com/v1/chat/completions`，使用 Bearer API Key，提交 `model` 和 `messages`。因此，本仓库客户端的基础地址采用 `https://platform.shuyanai.com/v1`。

[密钥与额度综合文档](https://doc.shuyanai.com/doc-8652765)同时列出 `GET /v1/models`，用于查询当前 Key 可调用的模型。先看模型列表，再把返回的模型标识写入环境变量，能减少模型名称和权限不匹配的问题。列表里有模型，并不表示该模型支持所有文本、多模态、工具调用或结构化输出参数。

数据工具属于另一个接入面。[官方 API Key 指南](https://doc.shuyanai.com/doc-8441886)区分模型 Key 与搜索阅读 Key。不要把聊天示例的地址、密钥直接套到 Reader 或 Search。

## 二、先在本地看清请求结构

本仓库提供[标准库 Python 示例](../../examples/README.md)。先执行：

```text
python examples/client.py --dry-run
```

这个步骤只展示请求结构，不联网，也不需要真实密钥。检查完成后，在本地设置 `SHUYANAI_API_KEY`，运行 `--list-models`；再设置 `SHUYANAI_MODEL` 并发送一条短问题。环境变量的具体写法见示例说明。

示例不会自动加载 `.env`。`.env.example` 只用于说明变量名称，不能把复制模板误认为已经完成配置。密钥不要写进文章、代码块、截图或 GitHub 文件。

## 三、如何判断接入已经完成

拿到 HTTP 成功状态只是第一步。还需要确认模型返回的内容符合业务要求、结束原因可接受，并记录实际模型与用量。文章中若出现延迟、成功率或成本结论，应补充测试时间、模型版本、样本数量与统计口径。

遇到鉴权失败，先核对 Key 类型、状态和模型权限；遇到限流，先检查调用频率和额度。发生超时后，服务端可能已经处理请求，直接重复发送可能产生重复费用。本示例默认不自动重试，生产应用应按业务容忍度制定策略。

## 四、遇到官方页面差异时如何处理

旧的 [Models 单页](https://doc.shuyanai.com/api-417863696)标注“开发中”，示例域名与综合文档不同。本文使用综合文档和聊天文档中的平台地址；实际接入前仍应核对控制台及最新文档。把差异记下来，比悄悄替换域名更方便后来者排查问题。
